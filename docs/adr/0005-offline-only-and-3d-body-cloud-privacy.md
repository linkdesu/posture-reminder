# ADR-0005：纯离线运行与 3D 人形点云的隐私边界

- **日期**：2026-10-28
- **状态**：已接受

## 背景

这个应用在家庭里观察孩子的脸和身体。把这条数据流发到任何地方——哪怕是“隐私友好”的云端——都会把本地的坐姿工具变成监控面，而家庭无法审计离开了设备的内容。与此同时，孩子需要正向反馈：黑屏加数字像考试，而映出自己身体的形象像一面镜子。

## 决策

PostureLab **从构造上就是离线的**：没有网络权限、没有 HTTP 客户端、没有分析端点。番茄钟历史（`Documents/pomodoro-history.json`）、会话日志、截图与设置（UserDefaults）都留在设备的应用沙盒内。家长统计页由纯函数从本地历史聚合；不上传任何内容，也没有账号。

孩子的镜像是一团**由前置 TrueDepth 深度图与人像分割遮罩合成的 3D 人形点云**——贴合人形的稀疏彩色点集，背景干净、没有点阵。渲染只使用深度与遮罩几何：原始 RGB 摄像头画面绝不显示、绝不落盘，也绝不离开设备。

## 影响

- 删除应用即删除全部家庭数据；统计页的「清空历史」是真实的本地删除。
- 形象无法显示衣物、房间或人脸，这正是重点：家长报告与孩子镜像需要的是体态，不是身份。
- 当前真机输入源只产出距离与俯仰角，点云仍由姿态关节点生成且没有人像分割遮罩；在相机运行下显示为空态。把 TrueDepth 深度与人像分割接入渲染器，并保持无 RGB 通路，是后续 ticket 的工作。
- 未来任何同步、备份或崩溃上报功能都会重开本 ADR；它不是可以顺手塞进去的实现细节。

## 修订（0.3 轮）

原决策中「原始 RGB 摄像头画面绝不显示」一条**废止**，其余条款（纯离线、无 RGB 落盘、无 RGB 离开设备）不变。

**修订后**：主页与设置页冷启动即启动输入源，真机在「开始专注」之前就有摄像头预览——`CameraPreview` 与 `ARSession` 共享会话，画面仅在本机屏幕上显示，不落盘、不上传，应用内不存在任何 RGB 落盘通路；统计页切出时停止相机。渲染 3D 点云的几何约束不变：点云只使用深度与遮罩几何（模拟器及无真机环境用 `BodyRig` 合成关节点与深度帧）。

**为什么改**：设置页新增「形象模式」开关（副标题即向用户声明：摄像头画面只在本机屏幕上显示，不保存、不上传；开时预览与点云一起出现，关时两者一起隐藏）。孩子要在开始专注前就看到自己正在被观察的这面「镜子」，预览与点云同时出现比冷启动后一片空白更诚实地传达隐私边界；而且既然预览只在本地屏幕显示、没有落盘与上传通路，屏幕预览不构成数据离开设备的新路径。「绝不落盘、绝不上传」仍是本 ADR 的硬边界，也是 `scripts/audit-sandbox.py` 与 `scripts/audit-offline.py` 持续审计的对象。

## 修订（0.4 深度版）

本次修订**撤销**上一轮「摄像头预览」的废止：任何构建都不得显示摄像头画面。

**修订后**：

- 主页只显示由 TrueDepth 深度数据生成的人形点云；尚未检测到人体时显示矢量人形轮廓。
- 整条几何链路只消费深度像素，不读取彩色视频帧像素；`AVCaptureVideoDataOutput` 仅作为 TrueDepth 会话启动所需的图连接存在，不安装 delegate、不访问其缓冲区。
- 不出现 `VNDetectHumanBodyPoseRequest` 或任何 Vision 人体姿态 API；关节由 `DepthJointSource` 从深度遮罩估计。
- 本轮及以后任何“回到预览”的改动都必须新开 ADR，而不是再次修订本节。

详见 ADR-0007。
