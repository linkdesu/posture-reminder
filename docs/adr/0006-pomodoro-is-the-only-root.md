# ADR-0006：番茄钟主页是应用唯一入口，旧阅读流程退役

- **日期**：2026-10-29
- **状态**：已接受

## 背景

应用曾同时存在两条用户侧流程：一条以「开始阅读」为入口的阅读流程（主页 → 校准 → 监测 → 小结 → 阅读设置），另一条是番茄钟。两条流程共用同一个协调器与同一条样本时钟，却各自拥有界面、导航与阶段；用户在真实使用中只会走番茄钟，阅读流程的入口、校准页与小结页因此成为无法抵达的代码与纸面流程。GLOSSARY 与 Q1 已确认：番茄钟是用户侧唯一主流程，`pomodoro_main` 是应用启动默认主界面。

## 决策

- 应用**无参启动即进入番茄钟主页** `pomodoro_main`，不再需要 `-pomodoro 1` 启动参数；该参数被删除，任何仍传入它的脚本都会被视为过时。
- 阅读流程的界面、阶段与导航（`HomeView`、`CalibrationView`、`MonitoringView`、`SummaryView` 以及阅读设置 `SettingsView`）与其会话存储一并退役。用户侧只剩三个界面：主页、设置页、统计页。
- `-settings 1` 与 `-report day|week|month` 仍是启动参数：它们是验收取证的直接入口，指向番茄钟设置页与统计页。
- 样本时钟、`MonitoringEngine`（体态监测）与 `SessionSummary`（每个专注阶段一条 `session_ended`）原样保留；退役的只是围绕它们的那层导航与存储。

## 影响

- 只有一条流程需要维护、验证与截图；`screen` 日志词汇只剩下 `pomodoro_main`、`pomodoro_settings` 与三个统计页名。
- 旧的会话存储（`sessions.json`）不再写入；已存在于设备上的文件保持原样，读取路径已删除。
- 静默 3 秒校准（ADR-0004）仍需在专注开始时实现；退役的校准页从来不是它的实现，因此这次删除不改变校准行为。
- `-pomodoro` 参数删除是对脚本与文档的破坏性变更：`verify-posture-lab` 技能、验收脚本与 UI 测试都已同步。
